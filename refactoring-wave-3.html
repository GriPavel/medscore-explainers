Рабочий цикл

Каждый шаг имеет stop-condition. В реализацию проходит ровно один кандидат, и только после доказательства проблемы.

Свежий baseline

Зафиксировать текущий HEAD, тесты, import boundaries и известные внешние причины красного.

Replay изменений

Восстановить 3–5 недавних cross-cutting фич: какие правила, owners и слои пришлось менять вместе.

Disproof pass

Искать контрдоказательства: может быть, hotspot законно концентрирует сложность и уже имеет одного владельца.

Один срез

Классифицировать дефект и выбрать минимальную ремедиацию. Layout — лишь один из вариантов.

Закрепить

Characterization, green-to-green, исполняемая граница, полный gate, единый релиз и rollback.

Hard gate

Нет доказанного competing authority, duplicated policy, leaking boundary или повторяющегося multi-owner change surface — нет рефакторинга. «Файл большой» и «его часто меняют» сами по себе не проходят.

Что считать доказательством

Архитектурное замечание обязано быть фальсифицируемым и привязанным к реальным изменениям, а не к вкусу автора обзора.

  • Одно доменное правило имеет несколько мест, способных независимо изменить его смысл.
  • Схожие изменения повторно требуют синхронных правок у нескольких владельцев.
  • Пассивные транспортные или storage-слои вынуждены знать новые варианты доменного понятия.
  • Внутренности одного модуля протекают в тесты и потребителей мимо публичного seam.
  • Есть bidirectional knowledge или обход существующей import/dependency границы.
  • Предложенная граница уменьшает replay-сценарий и не переносит сложность в сеть фасадов.
  • Для нового owner можно написать исполняемый контракт, который реально падает при нарушении.
  • Каждая отвергнутая гипотеза записана рядом с причиной, чтобы её не продавали повторно.

Ограничения запуска

Community-скилл — инструкция, а не доверенная бинарь. Его надо проверить, зафиксировать и подчинить локальным правилам проекта.

До изменений

Read-only из текущего состояния

  • Не трогать грязный общий root.
  • Не ставить диагноз по LOC и числу коммитов.
  • Локально проверить и pin-нуть выбранную версию skill.
  • Снять свежий green baseline вместо ссылки на старый прогон.
Если дефект доказан

Один concept-owned cutover

  • Изолированный worktree от свежего канона.
  • Никаких параллельных реализаций и вечных compatibility wrappers.
  • Focused gate после каждого шага, полный gate перед merge.
  • Один fleet-wide релиз с preflight, manifest и rollback.

Первый concept-owned cutover

Phase 1 · merged

Один authoritative runtime schema contract

Таблицы, views, sequences и control-function signatures теперь определены одним владельцем; dormant-state producer/verifier, ACL boundary и release preflight используют его напрямую. Исторические migrations оставлены самодостаточными и проверяются на точных ревизиях.

Phase 2 · merged

Текущий runtime проверяется на текущей схеме

Runtime preflight больше не закреплён на случайной старой migration: его schema authority — Alembic head, а точный контракт migration 072 остаётся в отдельном тесте. Второй order-dependent дефект закрыт у владельца test isolation: process-cache reader сбрасывается между ephemeral базами. Итоговый профильный gate: 296 тестов без падений.
