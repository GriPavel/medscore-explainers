Целевая архитектура: каждый факт вычисляет его владелец

Главное правило ремонта: протокол оркестрирует доказательства, но не угадывает внутреннюю логику writer-а и не доверяет mutable state caller-а.

Delivery fix: не импортировать список DB-only полей в протокол

Writer уже строит фактический outbox payload. В DbWriteResult он должен вернуть явный immutable-факт sheet_delivery_needed. Тогда not_required легален только при false, а malformed/неполное evidence отклоняется fail-closed.

queued / applied / confirmed → OKnot_required + delivery_needed=false → OKnot_required + delivery_needed=true/unknown → FAIL

Что меняем по каждому принятому выводу

Ни одного глобального rewrite. Шесть локальных трансформаций с конкретным владельцем контракта.

Что сознательно не делаем

Часть советов панели была привлекательной только количеством удалённых строк. Для fence это хреновый критерий.

Отклонено

Не ослабляем snapshot

  • Не заменяем frozen snapshot ссылкой на caller-visible command.
  • Не инлайним его в набор mutable preview-полей.
  • Не удаляем validation/tamper guards ради меньшего числа строк.
Сохраняем

Fail-closed и прежние policy outcomes

  • Неизвестное delivery evidence считается ошибкой.
  • Generation/timestamp остаются validated boundary.
  • Python capability — защита API от misuse/concurrency, не security sandbox против произвольной module introspection.
